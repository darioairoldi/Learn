# How MarkItDown works

> MarkItDown is best understood as a **dispatcher over pluggable, format-specific converters**, with a lightweight local core and opt-in escalation to LLMs and Azure services for hard inputs.

**Source:** [github.com/microsoft/markitdown](https://github.com/microsoft/markitdown) 📘 [Official]

## ⚙️ Interfaces

You can drive MarkItDown three ways.

**Command line** — the fastest path:

```bash
markitdown path-to-file.pdf > document.md
markitdown path-to-file.pdf -o document.md
cat path-to-file.pdf | markitdown          # piped input
```

**Python** — for pipelines:

```python
from markitdown import MarkItDown

md = MarkItDown(enable_plugins=False)   # set True to enable plugins
result = md.convert("test.xlsx")
print(result.text_content)              # also: result.markdown
```

**Docker** — for isolated runs:

```bash
docker build -t markitdown:latest .
docker run --rm -i markitdown:latest < your-file.pdf > output.md
```

## 🏗️ The converter model

MarkItDown routes each input to a **format-specific converter**. To keep the base install light, format support is delivered through **optional dependencies** you install per need:

```bash
pip install 'markitdown[all]'            # everything
pip install 'markitdown[pdf, docx, pptx]' # just these converters
```

Available extras include `[all]`, `[pptx]`, `[docx]`, `[xlsx]`, `[xls]`, `[pdf]`, `[outlook]`, `[az-doc-intel]`, `[az-content-understanding]`, `[audio-transcription]`, and `[youtube-transcription]`.

This modularity is the core of MarkItDown's "lightweight" posture: you pay for only the formats you touch.

## 🔌 The plugin system

Third-party **plugins are disabled by default**:

```bash
markitdown --list-plugins
markitdown --use-plugins path-to-file.pdf
```

You discover community plugins via the GitHub hashtag `#markitdown-plugin`, and author your own from the `markitdown-sample-plugin` package. A first-party example, **`markitdown-ocr`**, adds OCR to the PDF, DOCX, PPTX, and XLSX converters by extracting text from embedded images using **LLM Vision** (reusing the same `llm_client` / `llm_model` pattern; if no client is provided, OCR is silently skipped).

## 🤖 LLM integration

For PPTX and image files, MarkItDown can generate **image descriptions** by passing an LLM client:

```python
from markitdown import MarkItDown
from openai import OpenAI

md = MarkItDown(llm_client=OpenAI(), llm_model="gpt-4o", llm_prompt="optional custom prompt")
print(md.convert("example.jpg").text_content)
```

## ☁️ Azure integrations

Two optional Azure paths raise conversion fidelity for hard inputs.

- **Azure Document Intelligence** — cloud layout and OCR extraction. CLI: `markitdown file.pdf -o out.md -d -e "<endpoint>"`; Python: `MarkItDown(docintel_endpoint="<endpoint>")`.
- **Azure Content Understanding** — higher-quality conversion with **structured field extraction** (emitted as YAML front matter), **multimodal** support (documents, images, audio, and video), and configurable analyzers. Each converted file is a **billable Azure API call**.

The three tiers stack cleanly, so you escalate only where needed:

| Tier | Mechanism | Trade-off |
|---|---|---|
| Built-in converters | Local, format-specific, offline | Free; basic audio, no video |
| Azure Document Intelligence | Cloud layout / OCR extraction | Billable; better scanned-PDF and table fidelity |
| Azure Content Understanding | Cloud multimodal + field extraction | Billable; only option for video; structured fields |

## 🔒 Security model

MarkItDown performs I/O **with the privileges of the current process** — like `open()` or `requests.get()`, it can reach any resource the process can. In hosted or server-side use, treat these as requirements, not suggestions:

- **Sanitize untrusted input** — validate and restrict file paths, URI schemes, and network destinations; block private, loopback, link-local, and metadata-service addresses.
- **Call the narrowest method** — the general `convert()` accepts local files, remote URIs, and byte streams. Prefer `convert_local()`, `convert_stream()`, or `convert_response()` to limit what a call can reach.
