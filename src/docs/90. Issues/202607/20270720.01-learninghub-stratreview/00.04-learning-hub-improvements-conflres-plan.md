# Conflict resolution: route collisions between mounts and curated content

> **Status: draft.** Design + investigation plan. Investigation is complete; the recommended policy
> is a **proposal** pending the [§ Open decisions](#-open-decisions). The user asked to *"identify and
> go for a best approach"* — this plan commits to one. Parent: [strat-review overview](overview.md) ·
> [mount plan](00.01-learning-hub-improvements-mount-plan.md).

---

## 🎯 Goal

Choose and specify the **best approach** for what happens when a mount's `routePrefix` overlaps a
curated path (or another mount's prefix) — so collisions are **prevented** where possible and
**deterministic and visible** when they still occur.

## 🧭 Motivation

Once the renderer composes multiple sources (plan 01), two trees could claim the same route. Silent
merging or silent precedence would hide content and produce confusing, non-reproducible navigation. A
markdown-first site whose "content is the source of truth" must fail loudly on ambiguity.

## 🔎 Investigation: where collisions can arise (✅ done)

- **Merged listing at each level.** A `CompositeContentSource.ListChildrenAsync("")` concatenates the
  primary's top-level children with each mount's root. Two entries with the **same `Name`** would
  render as two nav nodes pointing at the same route — ambiguous.
- **Ambiguous fetch.** `GetAsync(key)` must pick *one* owning source. Without a rule, the first match
  wins by list order — non-obvious and fragile.
- **A precedent already exists.** `DynamicNavBuilder.RootInfra` reserves specific root names
  (`src`, `docs`, …). Reserved-namespace thinking is already in the codebase and can be extended to
  mount prefixes.
- **Two distinct moments.** A collision can be detectable at **startup** (static config, known curated
  top-level names) or only at **runtime** (a mount tree grows a folder that shadows curated content
  after the fact).

## 🧩 Recommended approach — prevention-first, primary-wins-and-warn (🟡 todo)

A two-layer policy:

1. **Prevent at configuration time (primary mechanism).** Every mount MUST declare a **unique
   `routePrefix`**. On startup, `CompositeContentSource` **validates**:
   - no two mounts share a `routePrefix` (or nest one inside another), and
   - no mount `routePrefix` equals a **reserved** or **known curated** top-level segment.

   A violation is a **fail-fast** startup error (clear message naming both sides) — the app refuses to
   start mis-mounted rather than serving ambiguous content. (🟡 todo — design decision)

2. **Resolve deterministically at runtime (defensive net).** If, despite validation, a key resolves
   in **both** the primary and a mount (e.g. a mount tree grows a shadowing folder post-startup):
   - **curated primary content always wins**,
   - the shadowed mount entry is **dropped from the merged listing** (never merged into one node), and
   - a **warning is logged** naming the mount id and the colliding path, and surfaced to the mount's
     provenance/health signal (plan 01 park-lot item).

   Precedence is fixed and documented, so behavior is reproducible. (🟡 todo — design decision)

**Why this over the alternatives:** "curated wins silently" hides the conflict; "last mount wins"
makes order matter invisibly; "merge both" produces duplicate/again-ambiguous nodes. Fail-fast on
config + fixed precedence + a visible warning is the only combination that is both **safe** and
**debuggable**.

## 🗺️ Decision table (✅ done)

| Situation | Detected | Policy |
|---|---|---|
| Two mounts, same `routePrefix` | Startup | **Reject** — fail fast |
| Mount prefix == reserved/curated top segment | Startup | **Reject** — fail fast |
| Mount prefix nests inside another mount | Startup | **Reject** — fail fast |
| Mount grows a folder shadowing curated content | Runtime | **Primary wins**, drop shadow, warn |
| Two mounts collide deep (post-startup) | Runtime | **Lower-`order` mount wins**, drop other, warn |

## 🪜 Proposed implementation phases (🟡 todo)

1. **Phase 0 — startup validation.** Implement `routePrefix` uniqueness + reserved/curated checks in
   `CompositeContentSource`; fail fast with a descriptive error. (🟡 todo)
2. **Phase 1 — runtime precedence.** Implement primary-wins (and lower-`order`-wins for mount↔mount)
   in the merged `ListChildrenAsync`/`GetAsync`, dropping shadows. (🟡 todo)
3. **Phase 2 — surface warnings.** Emit collision warnings to logs and the mount health signal so
   they are visible, not buried. (🟡 todo)

## ❓ Open decisions

- **D1-curated-segment-list** — is the "known curated top-level segments" set computed **dynamically**
  from the primary source at startup (recommended — always current) or maintained as a **static
  reserved list**? *Resolves:* user; dynamic requires a one-time primary listing at boot. *Gates:*
  Phase 0 validation source.
- **D2-fail-vs-skip** — on a startup collision, **fail the whole app** (recommended — safest) or
  **skip the offending mount and start** (more available, less safe)? *Resolves:* user's
  availability-vs-safety preference. *Gates:* Phase 0 behavior.

## 🔭 Discovery

- **DS1-case-and-encoding** — route matching must be case-insensitive and separator-normalized (the
  sources already normalize `\`→`/` and trim). *At implementation* → reuse the same normalization for
  collision comparison so `Docs` and `docs` are treated as colliding.

## 🅿️ Park lot

- **Mount aliasing** (intentionally overlaying a curated subtree to override it) — an advanced, opt-in
  feature that would invert the precedence rule. → `closed: contradicts the safety goal for v1`
- **Per-mount route rewriting** (serve a mount under a different prefix than its content). → `defer`
