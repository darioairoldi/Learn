## 🎯 The gathering problem

[Copilot billing](00.020-how-ghcp-billing-works.md) is <mark>Stream B</mark> in the platform, and it has a hard constraint the cloud streams don't: Copilot requests go to <mark>GitHub's service</mark>, not through a gateway you control. So you can't tap a per-request telemetry stream the way you can for a self-hosted Foundry gateway.

Instead, GitHub exposes usage through a set of <mark>**polled REST APIs and downloadable reports**</mark>. The good news: those sources are unusually rich — they already carry the <mark>**user**</mark>, <mark>***model**</mark>, <mark>**team**</mark>, and <mark>**credit**</mark> data that cloud billing lacks. The job for Bronze is to poll them on a schedule and land the raw payloads immutably.

Four source families matter, in priority order for cost:

1.  <mark>**Billing usage APIs**</mark> — the cost truth (credits and premium requests, per user, per model, per day).
2.  <mark>**Copilot Metrics API**</mark> — behavioral and adoption data (engagement, features, editors, models, languages).
3.  <mark>**Seat / user-management API**</mark> — the license basis and per-user last activity.
4.  <mark>**Supporting surfaces**</mark> — activity report, budgets, cost centers, and the audit log.

## 🧾 Source 1 — <mark>**Billing usage APIs**</mark> (the cost truth)

The <mark>**enhanced billing platform**</mark> exposes the <mark>**metered usage**</mark> that drives Copilot cost.  
These are the highest-value endpoints for attribution because they carry <mark>**user × model × day**</mark> granularity.

| Endpoint (organization) | What it returns |
|---|---|
| `GET /organizations/{org}/settings/billing/ai_credit/usage` | **AI credit usage line items**, filterable by <mark>`user`</mark>, <mark>`model`</mark>, <mark>`product`</mark>, and <mark>`year`/`month`/`day`</mark> |
| `GET /organizations/{org}/settings/billing/usage` | Total metered usage across products, per <mark>`date`</mark> and <mark>`sku`</mark>, with <mark>`repositoryName`</mark> |
| `GET /organizations/{org}/settings/billing/usage/summary` | Aggregated summary, filterable by <mark>`repository`</mark>, <mark>`product`</mark>, <mark>`sku`</mark> |
| `GET /organizations/{org}/settings/billing/premium_request/usage` | Premium-request usage (legacy unit), same schema and filters |

The AI-credit and premium-request reports return `usageItems[]` with these fields:

-   <mark>`product`</mark>, <mark>`sku`</mark>, <mark>`model`</mark>
-   <mark>`unitType`</mark>, <mark>`pricePerUnit`</mark>
-   <mark>`grossQuantity`</mark>, <mark>`grossAmount`</mark>
-   <mark>`discountQuantity`</mark>, <mark>`discountAmount`</mark>
-   <mark>`netQuantity`</mark>, <mark>`netAmount`</mark>

The general `usage` report adds <mark>`date`</mark>, <mark>`quantity`</mark>, and <mark>`organizationName`</mark> / <mark>`repositoryName`</mark>.

Key facts for ingestion:

-   <mark>Grain</mark>: you can pull per <mark>`user`</mark> and per <mark>`model`</mark> down to a single <mark>`day`</mark> — effectively per-user, per-model, per-day credit consumption.
-   <mark>Retention</mark>: the past 24 months are accessible.
-   <mark>Auth</mark>: organization admin or billing manager; requires the enhanced billing platform. User-level endpoints (`/users/{username}/settings/billing/...`) exist only for individually billed plans, not org-managed seats.

> This is the closest GitHub gets to a per-request cost feed. It's the primary input to `fact_ai_usage` and the allocation bridge for Stream B.

## 📊 Source 2 — <mark>**Copilot Metrics API**</mark> (behavioral data)

The <mark>**Metrics API**</mark> describes <mark>**how**</mark> Copilot is used — <mark>adoption</mark>, <mark>engagement</mark>, and <mark>code-generation activity</mark> — which powers unit economics (<mark>cost per active developer</mark>, <mark>acceptance rate</mark>) rather than cost itself.

The current API is <mark>**report-based**</mark>: each endpoint returns <mark>signed download links</mark> to report files generated daily, not inline JSON. Report variants exist at both org and enterprise scope:

| Report | Endpoint (org) | Grain |
|---|---|---|
| Organization metrics | `/orgs/{org}/copilot/metrics/reports/organization-1-day` (and `organization-28-day/latest`) | <mark>Aggregate org</mark>, daily |
| Per-user metrics | `/orgs/{org}/copilot/metrics/reports/users-1-day` (and `users-28-day/latest`) | <mark>Per user</mark>, daily |
| User-teams join | `/orgs/{org}/copilot/metrics/reports/user-teams-1-day` | <mark>One row per user-team pair</mark> |

Enterprise scope mirrors these (`enterprise-1-day`, `enterprise-28-day/latest`, `users-*`, `user-teams-*`).

The reports break usage down by <mark>**feature**</mark>, <mark>**editor**</mark>, <mark>**model**</mark>, and <mark>**language**</mark>, including active and <mark>**engaged users**</mark>, <mark>**code suggestions and acceptances**</mark>, <mark>**lines of code suggested/accepted**</mark>, <mark>**chat interactions**</mark>, and <mark>**pull-request summaries**</mark>.  
Join the <mark>**user-teams**</mark> report with the per-user report to compute team-level metrics.

Key facts for ingestion:

-   <mark>**Availability**</mark>: reports start from October 10, 2025, with historical data for up to one year.
-   <mark>**Prerequisite**</mark>: the "Copilot usage metrics" policy must be enabled for the enterprise.
-   <mark>**Auth**</mark>: `read:org` (organization) or `manage_billing:copilot` / `read:enterprise` (enterprise).
-   <mark>**Shape**</mark>: land the downloaded report files as-is — they're the raw artifact.

## 🪪 Source 3 — <mark>**Seat**</mark> and <mark>**user-management API**</mark>

The seat API gives the <mark>**license basis**</mark> (what you pay per seat) plus per-user last-activity signals.

| Endpoint | What it returns |
|---|---|
| `GET /orgs/{org}/copilot/billing` | <mark>`seat_breakdown`</mark> (total, added_this_cycle, pending_cancellation, pending_invitation, active_this_cycle, inactive_this_cycle), feature policies (`ide_chat`, `platform_chat`, `cli`), `plan_type` |
| `GET /orgs/{org}/copilot/billing/seats` | Per-seat: `assignee` (login, id), `assigning_team`, `pending_cancellation_date`, `last_activity_at`, `last_activity_editor`, `last_authenticated_at`, `created_at`, `plan_type` |
| `GET /orgs/{org}/members/{username}/copilot` | Single-user seat detail |

Key facts:

-   <mark>`last_activity_editor`</mark> tells you which editor the user last used — a coarse channel signal.
-   `last_activity_at` requires the user to have <mark>IDE telemetry enabled</mark>; it's retained for 90 days, then reset to null.
-   <mark>Auth</mark>: `manage_billing:copilot` or `read:org`.

## 🧭 Source 4 — Activity report, budgets, cost centers, audit log

Supporting surfaces fill gaps and add governance context.

-   <mark>Copilot activity report</mark> (CSV, from the Access management page, refreshed every 30 minutes): fields `report_time`, `login`, `last_authenticated_at`, `last_activity_at`, and <mark>`last_surface_used`</mark> (IDE editor + version, or GitHub.com feature name). It covers GA features across IDE, GitHub, CLI, and Mobile. Retention is a rolling 90 days.
-   <mark>Budgets API</mark> (`GET /organizations/{org}/settings/billing/budgets`): budget definitions scoped to `enterprise` / `organization` / `repository` / `cost_center` / `multi_user_customer` / `user`, with `budget_product_sku` of <mark>`ai_credits`</mark> or <mark>`premium_requests`</mark> and an `effective_budget.consumed_amount`. Useful for tracking consumption against guardrails per scope.
-   <mark>Cost centers</mark>: the enhanced-billing grouping that budgets and usage can be scoped by — the direct bridge to `dim_organization` (cost center) for chargeback.
-   <mark>Audit log</mark>: Copilot configuration and seat-lifecycle events (policy changes, seat assign/unassign). Not per-request usage, but the source of truth for governance and seat history.

## 🧩 Coverage by Copilot flavour

Different Copilot surfaces land in different sources. This matrix shows where each flavour's data comes from.

| Copilot flavour | Cost (credits) | Behavioral metrics | Activity / seat | Notes |
|---|---|---|---|---|
| IDE code completions | Not billed (unlimited) | Metrics API (suggestions, acceptances, lines of code, by editor/model/language) | `last_activity_editor`; activity report (IDE) | Completions never draw credits |
| IDE chat / edits / agent mode | Billing usage (`ai_credit`, by `model`) | Metrics API (chat, by editor/model) | Activity report (IDE) | Credit-consuming |
| GitHub.com chat | Billing usage | Metrics API (dotcom chat, by model) | Activity report (GitHub) | |
| Pull-request summaries | Billing usage | Metrics API (dotcom PRs, by repo/model) | Activity report (GitHub) | |
| Copilot code review | Billing usage | Limited | Activity report (GitHub) | Fixed-cost feature |
| Copilot cloud agent (remote) | Billing usage (dedicated SKU) | Limited | Activity report (GitHub: cloud agent) | Dedicated SKU since Nov 1, 2025 |
| Copilot CLI (local agent) | Billing usage | Limited | Activity report (CLI); seat `cli` policy | |
| Copilot Spark | Billing usage (dedicated SKU) | Not fully recorded yet | — | Preview |
| Copilot Spaces | Billing usage | Not fully recorded yet | — | Preview |
| Copilot SDK / third-party agents | Billing usage (credits) | Limited | — | Billed as credits |

The pattern: <mark>cost for every credit-consuming flavour is in the billing usage API</mark> (with `model`), while <mark>behavioral depth is richest for IDE and dotcom features</mark> in the Metrics API. Agents, CLI, Spark, and SDK are visible in cost (via SKUs/credits) but thinner on behavioral telemetry.

## 📡 The telemetry reality

Three realities shape what's achievable:

1.  <mark>No customer-facing per-request stream</mark>. GitHub doesn't emit a raw event per Copilot request to you. The finest cost grain available is the billing usage API's <mark>per-user × per-model × per-day</mark> rows. Plan attribution around that grain, not per-request.
2.  <mark>Client telemetry must be enabled</mark>. `last_activity_at` and some metrics depend on IDE telemetry being on; missing telemetry undercounts activity (especially in non-VS Code IDEs).
3.  <mark>Self-hosted is the only per-request path</mark>. If you route models yourself through the Copilot SDK or a bring-your-own-key proxy, that proxy becomes a gateway you *can* instrument per request — but that's a different architecture from standard managed Copilot.

## 🥉 Landing it in Bronze

Poll each source on a schedule and land the raw payloads append-only, following the [Bronze contract](02.000-bronze-silver-gold-schemas.md).

| Bronze table | Source | Grain | Cadence |
|---|---|---|---|
| `bronze_ghcp_billing_usage_raw` | `ai_credit/usage` + `premium_request/usage` + `usage` | User × model × sku × day | Daily (day-filtered) |
| `bronze_ghcp_metrics_report_raw` | Metrics API report files (org, users, user-teams) | Aggregate + per-user daily | Daily (latest + backfill) |
| `bronze_ghcp_seats_raw` | `copilot/billing` + `copilot/billing/seats` | Per seat (snapshot) | Daily snapshot |
| `bronze_ghcp_budgets_raw` | Budgets API | Per budget scope | Daily (optional) |
| `bronze_ghcp_activity_report_raw` | Activity report CSV | Per user (surface) | Optional |
| `bronze_ghcp_audit_events_raw` | Audit log | Per event | Streaming/optional |

Standard ingestion metadata (ingestion timestamp, source endpoint, batch ID, checksum) applies to every table, exactly as for the cloud streams.

Canonical mapping in Silver:

-   <mark>`login`</mark> → `dim_user`; <mark>team</mark> (from user-teams / assigning_team) → `dim_team`; <mark>org / cost center</mark> → `dim_organization`; <mark>`model`</mark> → `dim_model`; <mark>date</mark> → `dim_time`; <mark>editor</mark> (`last_activity_editor`) → `dim_access_channel`.
-   <mark>`netAmount` / credits</mark> from billing usage → the usage-cost component of `fact_ai_usage` and the allocation bridge.
-   <mark>Seat count × plan price</mark> → the license-cost component (kept separate from usage cost, per the billing article).
-   <mark>Metrics</mark> (acceptances, lines of code, engaged users) → engagement measures for unit economics, joined by user and day.

## ⚠️ Gaps and limitations

-   <mark>Aggregation floor</mark>: some metrics reports suppress data below a minimum number of active users to protect privacy — small orgs may see gaps.
-   <mark>Preview features</mark>: Spark and Spaces aren't fully represented in metrics/activity reports yet; rely on billing SKUs for their cost.
-   <mark>Telemetry dependence</mark>: activity and `last_activity` undercount when IDE telemetry is off or the IDE is outdated.
-   <mark>Two units across time</mark>: historical data may be in premium requests while current data is in credits — tag each Bronze row with its unit so trends don't mix across the June 1, 2026 boundary.
-   <mark>Reconciliation</mark>: dashboards, APIs, and exported reports aggregate the same telemetry differently; reconcile against the billing usage API (the invoice-aligned source) rather than the metrics dashboard.

## ✅ Key takeaways

-   There's **no per-request telemetry stream** for managed Copilot — gather usage by **polling GitHub's APIs and reports** into Bronze.
-   The **billing usage APIs** are the cost truth, at **per-user × per-model × per-day** grain (`ai_credit/usage`, `premium_request/usage`, `usage`), 24-month retention.
-   The **Metrics API** (report download links) supplies behavioral depth — engagement, features, editors, models, languages — at org, per-user, and team level.
-   The **seat API** supplies the license basis and `last_activity_editor`; **budgets, cost centers, and the audit log** add guardrail and governance context.
-   **Cost is visible for every flavour** via credits/SKUs; **behavioral telemetry is richest for IDE and dotcom** features and thinner for agents, CLI, Spark, and SDK.
