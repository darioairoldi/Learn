## 🎯 Scope and the dashboard goal

This document turns the architecture in [00.000-overview.md](00.000-overview.md) and the ingestion contract in [01.000-read-azure-billing.md](01.000-read-azure-billing.md) into **concrete table schemas** for a single AI-cost dashboard that works across Azure, GCP, and AWS.

The dashboard must answer, for any time window, "how much did AI cost, broken down by":

-   <mark>Business lenses</mark>: company / cost center, team, user.
-   <mark>Technical lenses</mark>: cloud provider, subscription/project, resource group, resource, service/meter.
-   <mark>AI lenses</mark>: AI provider, model family, model deployment, access channel, request type, processing type.
-   <mark>Behavioral lenses</mark>: client IP / network zone, prompt type, response type, quality (malformed / retry overhead), cache hit ratio, commitment (PTU) utilization.

The central constraint stays the same throughout the model: **billing is the financial truth, telemetry only redistributes billed cost inside a bucket**. The schemas below enforce that with an explicit `cost_bucket_key` and an allocation bridge.

## 🧭 Modeling principles

1.  <mark>Adopt FOCUS as the canonical cost shape.</mark> Azure Cost Management, GCP BigQuery export, and AWS CUR all publish (or map cleanly to) the FinOps FOCUS specification. Your observed export columns (`BilledCost`, `BillingCurrency`, `ConsumedService`, `x_*`) are already FOCUS. Normalize every provider to FOCUS in Silver so `fact_cloud_cost` is provider-agnostic.
2.  <mark>Two fact families, one bridge.</mark> `fact_cloud_cost` (money) and `fact_ai_usage` (usage) never join directly; they meet through `fact_cost_allocation` (allocated money).
3.  <mark>Conformed dimensions with surrogate keys.</mark> Every dimension gets a stable surrogate key. Membership-style dimensions (user, team, org, model lifecycle) are SCD Type 2 so historical reports reflect state at request time.
4.  <mark>Keep raw next to canonical.</mark> Bronze is immutable and append-only; Silver adds canonical fields but never deletes source columns needed for audit.
5.  <mark>Grain discipline.</mark> Bronze grain = one source record. `fact_cloud_cost` grain = one billed line item per day. `fact_ai_usage` grain = one request (or one hourly usage bucket for high-volume workloads). `fact_cost_allocation` grain = one allocated amount to one target.

## 📐 The dimension catalog

These conformed dimensions are shared by all facts. Columns marked **SCD2** carry `valid_from_utc`, `valid_to_utc`, `is_current`.

| Dimension | Key | Core attributes | Notes |
|---|---|---|---|
| `dim_time` | `date_key` (yyyymmdd) | date, day, week, month, quarter, year, is_weekend | Add `dim_hour` for intraday deep dives. |
| `dim_provider` | `provider_key` | cloud provider (azure/gcp/aws), billing account | Cloud vendor, not model owner. |
| `dim_billing_scope` | `billing_scope_key` | subscription_id / project_id / linked_account, scope_type | Provider org boundary. |
| `dim_resource_group` | `resource_group_key` | resource_group_name, owner_tag, environment_tag | From billing + tags. |
| `dim_resource` | `resource_key` | resource_id, resource_type, resource_name, region | Physical/billed resource. |
| `dim_service` | `service_key` | service_category, meter_category, meter_subcategory, sku | FOCUS `ServiceName`/`x_Meter*`. |
| `dim_ai_provider` | `ai_provider_key` | canonical provider (OpenAI/Anthropic/Microsoft/Meta/Google), raw_provider_label | Model/runtime owner. |
| `dim_model` | `model_key` **SCD2** | canonical_model_family, provider_model_name, deployment_id, modality, lifecycle_status, commitment_type (payg/PTU) | Channel-agnostic identity. |
| `dim_access_channel` | `channel_key` | channel (foundry / github-copilot / copilot-sdk / api-direct / m365 / bedrock / vertex) | Same model, many channels. |
| `dim_request_type` | `request_type_key` | request_type (chat/embeddings/image/speech/rerank/batch/agent), taxonomy_version | Versioned taxonomy, `unknown` fallback. |
| `dim_processing_type` | `processing_type_key` | processing_type (text/image/audio/translation/document), taxonomy_version | Versioned, `unknown` fallback. |
| `dim_prompt_type` | `prompt_type_key` | prompt_type (free-form/template/tool-call/RAG), taxonomy_version | Behavioral. |
| `dim_response_type` | `response_type_key` | response_type (text/json-schema/tool-call/multimodal), taxonomy_version | Behavioral. |
| `dim_user` | `user_key` **SCD2** | user_principal (or pseudonym), display_name, is_service_account | Row-level security target. |
| `dim_team` | `team_key` **SCD2** | team_name, department, parent_team_key | Membership at request time. |
| `dim_organization` | `org_key` **SCD2** | company / legal_entity, cost_center, business_unit, chargeback_code | Chargeback anchor. |
| `dim_application` | `application_key` | application_id, product, repository, environment | Engineering ownership. |
| `dim_environment` | `environment_key` | environment (dev/test/stage/prod) | Often also a tag. |
| `dim_region` | `region_key` | region, geo, availability_zone | |
| `dim_client_network` | `client_network_key` | client_ip, ip_range_cidr, network_zone (corp/vpn/public), geo_country | **New lens you asked for.** Store hashed/truncated IP if privacy requires. |
| `dim_allocation_rule` | `rule_key` | rule_id, rule_version, weighting_basis (tokens/requests/units), confidence_default | Governs the bridge. |

Recommended extra lenses worth adding (high signal for AI FinOps):

-   <mark>Commitment / PTU</mark>: track provisioned-throughput utilization vs pay-go so idle reserved capacity is visible (`commitment_type` on `dim_model`, plus an optional `fact_commitment_utilization`).
-   <mark>Cache hit</mark>: cached input tokens are billed cheaper — a `cache_hit_ratio` measure surfaces prompt-caching savings.
-   <mark>Agent / workflow</mark>: `agent_id` / `workflow_id` on usage to attribute multi-step orchestration cost.

## 🥉 Bronze layer schemas

Bronze is **append-only and immutable**. Every table carries the same ingestion metadata envelope; source columns are stored verbatim.

### Standard ingestion metadata (all Bronze tables)

| Column | Type | Meaning |
|---|---|---|
| `ingestion_timestamp_utc` | timestamp | When the row landed. |
| `source_system` | string | e.g. `azure-cost-management-export`. |
| `source_scope_id` | string | Subscription / project / org scope. |
| `source_file_name` | string | Origin file (for file-based sources). |
| `source_file_etag_or_hash` | string | Idempotency / dedup key. |
| `ingestion_batch_id` | string | Batch correlation ID. |
| `source_mode` | string | `api` or `export` (flags temporary dashboard exports). |

### `bronze_azure_cost_export_raw` (FOCUS)

Verbatim FOCUS/usage-details columns. Minimum audited set:

| Raw column | FOCUS role |
|---|---|
| `ChargePeriodStart` / `ChargePeriodEnd` / `UsageDate` | billing date |
| `BilledCost` / `EffectiveCost` / `CostUSD` / `Cost` | cost amount(s) |
| `BillingCurrency` / `Currency` | currency |
| `SubscriptionId` / `x_SubscriptionName` | billing scope |
| `ResourceId` / `ResourceName` / `ResourceType` | resource |
| `ResourceGroupName` | resource group |
| `ServiceName` / `ConsumedService` / `MeterCategory` / `MeterSubCategory` | service/meter |
| `SkuId` / `SkuPriceId` / `x_Sku*` | SKU / pricing |
| `Tags` (JSON) | ownership, environment, cost center |
| `RegionId` / `RegionName` | region |

> GCP (`bronze_gcp_billing_export_raw`) and AWS (`bronze_aws_cur_raw`) follow the same pattern with their native columns; Silver maps all three into the same FOCUS canonical fields.

### `bronze_gateway_request_log_raw` (attribution truth)

The gateway (APIM / AI Gateway) log is where **user, client IP, model, tokens, and request type** originate.

| Raw column | Meaning |
|---|---|
| `request_id` | unique request ID |
| `event_timestamp_utc` | request time |
| `caller_principal` | user/service principal (or pseudonym) |
| `group_claims` | group/team claims snapshot |
| `client_ip` | caller IP → `dim_client_network` |
| `api_path` / `operation` | endpoint → request type mapping |
| `model_deployment` | provider model/deployment label |
| `input_tokens` / `output_tokens` / `cached_tokens` | usage units |
| `billable_units` | provider billable units when exposed |
| `status_code` / `error_class` | success/failure |
| `latency_ms` | latency |
| `application_id` / `environment` | app + env |
| `subscription_id` / `resource_id` | links usage to a billing bucket |

### `bronze_app_trace_raw`, `bronze_agent_trace_raw`

Application and agent-orchestration traces (prompt type, response type, malformed flags, retry chains, `agent_id` / `workflow_id`, per-turn tokens).

### `bronze_github_copilot_usage_raw`, `bronze_m365_usage_raw`

Seat/interaction telemetry stored unchanged (org, team, repository, active users, acceptance rate, model mix when present).

## 🥈 Silver layer processing structure

Silver runs **asynchronously**, triggered by Bronze availability, and is fully **re-runnable without re-ingesting**. Each source has its own pipeline; all converge on the same canonical entities.

``` mermaid
flowchart LR
    B[Bronze raw] --> N1[1 Parse and dedup]
    N1 --> N2[2 Schema conformance to FOCUS / canonical usage]
    N2 --> N3[3 Identity enrichment SCD2]
    N3 --> N4[4 Taxonomy mapping versioned]
    N4 --> N5[5 Canonical key creation]
    N5 --> N6[6 Quality flags and confidence]
    N6 --> F1[fact_cloud_cost]
    N6 --> F2[fact_ai_usage]
    N6 --> D[conformed dim staging]
```

Step-by-step contract:

1.  <mark>Parse and dedup</mark> — reject duplicates using `source_file_etag_or_hash` + natural keys (`request_id`, billing line-item key). Idempotent by design.
2.  <mark>Schema conformance</mark> — map each source's columns into canonical fields: cost sources → FOCUS `fact_cloud_cost` columns; telemetry sources → canonical `fact_ai_usage` columns. Pick one authoritative `cost_amount`; keep the alternate as auxiliary.
3.  <mark>Identity enrichment</mark> — resolve `caller_principal` → `user_key`, then `team_key` and `org_key` using the directory snapshot valid at `event_timestamp_utc` (SCD2 lookup). Resolve `client_ip` → `client_network_key`.
4.  <mark>Taxonomy mapping</mark> — map `api_path`/`operation` → `request_type_key`; classify `processing_type`, `prompt_type`, `response_type`. Every taxonomy is versioned; unmapped values go to an `unknown` bucket that is monitored as a data-quality KPI.
5.  <mark>Canonical key creation</mark> — compute the `cost_bucket_key` that ties usage to the exact billing partition it can redistribute:

    ``` text
    cost_bucket_key = <billing_month>|<subscription_id>|<resource_group_name>|<resource_type>|<meter_category>
    ```

    and assign all surrogate dimension keys.
6.  <mark>Quality flags and confidence</mark> — set malformed-prompt / malformed-response flags, retry lineage, and a per-row `confidence_score` for later allocation.

Silver outputs (canonical, allocation-ready):

-   `fact_cloud_cost` — one row per billed line item per day, carrying `cost_bucket_key`.
-   `fact_ai_usage` — one row per request (or hourly bucket), carrying `cost_bucket_key`, all usage measures, and all dimension keys.
-   Conformed dimension staging tables (feed Gold SCD2 merges).

### `fact_cost_allocation` (the bridge — every dollar, once)

| Column | Type | Notes |
|---|---|---|
| `allocation_id` | bigint (PK) | surrogate |
| `date_key` | int | |
| `cost_bucket_key` | string | source billing bucket |
| all dimension keys | int | resource, group, model, channel, request type, processing type, **user, team, org, client_network**, application |
| `allocated_cost` | decimal | portion of billed cost |
| `usage_weight` | decimal | numerator used |
| `bucket_usage_total` | decimal | denominator used |
| `rule_key` | int | → `dim_allocation_rule` |
| `confidence_score` | decimal | |
| `is_unattributed` | bool | usage-missing fallback |

The bridge enforces the accounting identity per bucket and period:

$$
\sum allocated\_cost_{bucket} = billed\_cost_{bucket}
$$

### Consumer marts (Gold)

-   `mart_finops_daily` — cost by provider, resource group, service, org/cost center, forecast vs budget.
-   `mart_model_economics` — cost per 1K tokens, cost per successful request, by model family × channel.
-   `mart_quality_overhead` — malformed / retry cost overhead by prompt & response type.
-   `mart_chargeback` — allocated cost by company → cost center → team → user (the chargeback export).

## 💰 Allocation walkthrough end to end

1.  Silver produces `fact_cloud_cost` with `billed_cost` per `cost_bucket_key`.
2.  Silver produces `fact_ai_usage` with a `usage_weight` (token count is the recommended primary weight, requests second, billable units third) and the same `cost_bucket_key`.
3.  Gold computes, **inside each bucket only**:

$$
allocated\_cost_{i} = billed\_cost_{bucket} \times \frac{usage\_weight_{i}}{\sum usage\_weight_{bucket}}
$$

4.  Any bucket with no matching usage routes its cost to `is_unattributed = true` — never to synthetic cost.
5.  Reconciliation gate blocks publish unless per-bucket allocated totals equal billed totals.

## 📊 Dashboard slices this model enables

Because all facts share conformed keys, a single Power BI semantic model over `fact_cost_allocation` supports every slice you named plus the extras:

-   Company / cost center → team → user drill-down (chargeback).
-   Client IP / network zone (corp vs VPN vs public) anomaly detection.
-   Request type × model × channel intersection.
-   Provider (OpenAI/Anthropic/Microsoft) × processing type.
-   Prompt type × response type with malformed-cost overlay.
-   PTU commitment utilization vs pay-go, and prompt-cache savings.

## ✅ Schema definition of done

-   `fact_cloud_cost` reconciles to provider exports for each closed month (variance = 0).
-   `fact_cost_allocation` satisfies the per-bucket identity for 100% of buckets.
-   Unattributed usage volume < 2% after two full cycles.
-   `unknown` share monitored for every versioned taxonomy (request, processing, prompt, response).
-   All membership dimensions (user, team, org, model lifecycle) are SCD2 and reproduce point-in-time reports.
-   The same star model validated with at least one non-Azure provider via the FOCUS canonical layer.

## 📚 References

[**FinOps FOCUS specification**](https://focus.finops.org/) 📘 \[Official\]\
Description: The open, cross-cloud billing schema that unifies Azure, GCP, and AWS cost data. Use it as the canonical shape for `fact_cloud_cost` so provider exports become directly comparable. It is the authoritative source for column semantics like `BilledCost` and `EffectiveCost`.

[**Azure Cost Management — FOCUS dataset export**](https://learn.microsoft.com/azure/cost-management-billing/dataset-schema/cost-usage-details-focus) 📘 \[Official\]\
Description: Field-level reference for the FOCUS-formatted Azure export whose columns appear in the sample data. Use it to build durable Bronze-to-Silver mappings. It is the key reference for reconciliation-safe transformations.

[**Understand usage details fields for Azure billing**](https://learn.microsoft.com/azure/cost-management-billing/automate/understand-usage-details-fields) 📘 \[Official\]\
Description: Semantics of legacy Azure billing line-item fields. Use it when an export flavor predates FOCUS or mixes column families. It disambiguates `CostUSD` vs `Cost` vs `BilledCost`.

[**Google Cloud billing export to BigQuery**](https://cloud.google.com/billing/docs/how-to/export-data-bigquery) 📘 \[Official\]\
Description: Standard GCP billing export path feeding `bronze_gcp_billing_export_raw`. Use it to reach FOCUS parity with Azure. It is authoritative for GCP detailed billing records.

[**AWS Cost and Usage Reports (CUR)**](https://docs.aws.amazon.com/cur/latest/userguide/what-is-cur.html) 📘 \[Official\]\
Description: AWS billing truth feeding `bronze_aws_cur_raw`. Use it to normalize AWS into the same canonical star model. It is authoritative for CUR schema and invoice reconciliation.
