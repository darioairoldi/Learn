# Navbar Navigation & Status-bar — Metadata Push Improvement Plan

## 🎯 Objective

Make navigation metadata (per-folder **article count** and **newest-article** date/author) update **event-driven and incrementally** instead of by polling:

- The **server** computes the authoritative recursive aggregate once and **pushes deltas** when content changes.
- The **client** keeps its cached tree and applies deltas locally (bubble-up), so a single leaf change updates only the affected branch and the footer total — no level refetch.

This preserves the current strengths (tiny lazy per-level payloads, client-side count maintenance, SmartCache) and removes the polling machinery.

## 🧭 Motivation

Today the article count travels through five representations and is maintained by **two polling loops**:

1. **Cold-start convergence** — `DynNav.ConvergeCountsAsync()` polls `/_nav/children` every 5 s, up to 48 times (~4 min), waiting for the server's background tree-walk to fill counts.
2. **Change refresh** — content writes bump a version; clients must poll `/_nav/version` and refetch.

Both are indirect, add latency, and cannot reflect a create/update/delete in real time. A push channel carrying **folder-metadata deltas** covers cold-start *and* every later change with one mechanism, and lets the client update by pure local arithmetic.

## 📋 Current state (analysis — reference)

| Concern | Where | Behavior |
|---|---|---|
| Authoritative recursive count | `DynamicNavBuilder.WalkAsync` → `_folderAgg` | Filled by startup tree-walk (`GetIndexAsync`) |
| Per-level payload | `NavChild.ArticleCount` / `LatestArticleUtc` | Seeded from `_folderAgg` or `metadata.yml` |
| Server cache | `CachedDynamicNavBuilder` (SmartCache, path-keyed) | `Invalidate(path)` bumps `Version` |
| Client transport | `HttpNavProvider` | Caches in-flight task per prefix |
| Client bubble-up | `DynNavNode.ReportCount` / `_childCounts` | Leaf→parent→root sum |
| Footer aggregation | `NavStats.SetRoot` / `SetSelectedSection` / `SetHoverSection` | Sums roots → `TotalArticles`; two-tier section line |
| Cold-start poll | `DynNav.ConvergeCountsAsync` | 5 s × 48 |
| Change signal | `/_nav/version` + `POST /_nav/invalidate` | Version poll |

## 🎨 Design direction (agreed)

A lightweight real-time channel pushing **folder-metadata deltas**:

```text
MetadataChanged { path, delta, latestUtc, author }   // e.g. path="03.00-tech/02.01-azure", delta=+1
CountsReady     { rootAggregates[] }                 // once, when startup warm-up fills _folderAgg
```

**Client reaction (pure local arithmetic, no refetch):**
- `MetadataChanged` → adjust `ArticleCount` on every cached node whose prefix is an **ancestor** of `path` (roots always cached → footer total stays correct; loaded intermediate sections stay correct; unloaded ones fetch fresh truth when later expanded). Update newest date/author if newer.
- `CountsReady` → seed root counts once → **replaces** `ConvergeCountsAsync`.

**Keep:** `NavChild.ArticleCount` initial seeding, `DynNavNode` bubble-up, `NavStats`, SmartCache.
**Remove:** `ConvergeCountsAsync` loop; `/_nav/version` polling as the *primary* refresh (retain only as reconnect fallback).

## ✅ Resolved decisions

- **D1-transport → SignalR.** House-consistent (`IQPilot.csproj` already references `Microsoft.AspNetCore.SignalR.Client 8.*`; strat-review plans name SignalR). WASM client has no ref yet → add the package (**DS1 resolved: absent → add**).
- **D2-prod-trigger → publish from the `/_nav/invalidate` endpoint handler.** Every content path already calls it; no separate blob change feed needed.
- **D3 → absolute-aggregate-per-ancestor.** On change, push the **new absolute `ArticleCount` + newest date/author for the changed folder and each ancestor up to root**. The client *replaces* the cached count on each ancestor node (every ancestor keeps its own count in metadata). No old/new diffing, no drift (**DS2 resolved: recompute the subtree via the index walk, then read each ancestor's aggregate**).
- **D4-fallback → keep `/_nav/version` polling as a low-frequency reconnect fallback** (robustness when the socket drops); it is no longer the primary refresh.
